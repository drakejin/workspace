# ADR-0001 결제 요청 멱등 키

## 결정

order-api 가 결제 대행사로 보내는 모든 결제 요청에 `IdempotencyKeyHeader`(`Idempotency-Key`)를 붙인다.
키는 `order_id` + 결제 시도 번호로 만든다. 같은 키의 재요청은 대행사가 첫 응답을 그대로 돌려준다.

## 대안

- 서버 측 중복 검사 테이블: 대행사 타임아웃 뒤 늦게 도착한 성공 응답을 놓친다.
- 클라이언트 재시도 금지: 네트워크 순단 때 주문이 결제 대기에 멈춘다.

## 에피소드

- 배경: 결제 타임아웃 후 재시도에서 이중 결제가 2건 발생 (예시 이슈 ORDER-42)
- 선택지와 결정: 중복 검사 테이블 / 재시도 금지 / 멱등 키 중 멱등 키
- 이유: 대행사가 멱등 키를 지원하고, 늦게 오는 성공 응답까지 같은 결과로 묶인다
- 그때의 생각: 키 생성 규칙이 결제 시도 번호에 기대는 게 찜찜하다
